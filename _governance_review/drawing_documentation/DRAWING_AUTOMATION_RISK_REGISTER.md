## 1. Risk Assessment Framework

This register identifies the technical, geometric, API, and operational risks associated with automated Revit drawing and documentation production, along with deterministic mitigation protocols.

- **Severity Levels:** `CRITICAL` (causes Revit crash, document corruption, or data loss), `HIGH` (causes drawing rejection or unreadable sheets), `MEDIUM` (causes minor visual defects or retry overhead), `LOW` (cosmetic).
- **Likelihood:** `HIGH` ($> 50\%$), `MEDIUM` ($20\%\text{--}50\%$), `LOW` ($< 20\%$).

## 2. Risk Matrix Table (R-DRW-01 through R-DRW-12)

| Risk ID | Risk Title & Description | Severity | Likelihood | Root Cause / Impact | Mitigation Strategy | Fallback / Recovery Mechanism |
|---|---|---|---|---|---|---|
| **R-DRW-01** | **Dimension Reference Invalidation** | `HIGH` | `MEDIUM` | In Revit API, `doc.Create.NewDimension` requires valid `Reference` handles. If underlying model geometry is regenerated or edited, reference handles can become stale, causing Revit to throw `InvalidOperationException` or delete the dimension string. | Query stable planar faces via `HostObjectUtils.GetSideFaces` or use element centerlines/grid curves rather than transient edge references. | If face reference fails, dimension to grid lines or Level datums; never place orphan floating text. |
| **R-DRW-02** | **Viewport Label Offset Drift** | `HIGH` | `HIGH` | Custom viewport types or user templates often have arbitrary label positions or unplaced titles. Relying on `vp.GetLabelOutline()` before the view is placed or before `doc.Regenerate()` can return empty or uncalibrated coordinates. | Always enforce `doc.Regenerate()` immediately after `Viewport.Create` before sampling `GetLabelOutline()`. If label outline is empty, apply a deterministic fallback label reservation box: Width $= \text{BoxWidth}$, Height $= 18.0\text{ mm}$ located $5.0\text{ mm}$ below the lower edge. | Apply fallback reservation box to ensure zero label collisions regardless of viewport type settings. |
| **R-DRW-03** | **Non-Standard Titleblock Orientation & Stamps** | `HIGH` | `MEDIUM` | Projects frequently use custom title blocks with horizontal bottom stamps (ISO) or portrait orientation instead of standard landscape right-column stamps. Hardcoded margin deductions ($14\%$ on right) result in wasted space or viewport collisions. | Inspect titleblock aspect ratio ($W/H$). If $W < H$, classify as Portrait. Query sub-elements of `OST_TitleBlocks` to find title text parameter boxes to deduce whether the stamp is on the right, bottom, or corner. | If stamp detection is ambiguous, use safe default margins: $20\text{ mm}$ left, $15\text{ mm}$ top/bottom/right. |
| **R-DRW-04** | **Schedule Row Overflow Beyond Sheet** | `MEDIUM` | `HIGH` | Large schedules (e.g., 50 doors or 100 windows) have physical heights exceeding the vertical canvas height ($> 280\text{ mm}$ on A3), causing the table to spill out of the sheet border. | Calculate estimated schedule height: $H = H_{\text{title}} + (\text{Rows} \times 6.0\text{ mm})$. If $H > \text{AvailableHeight}$, invoke `ScheduleSheetInstance.Segment()` to split into adjacent vertical columns. | If split columns still exceed Zone 4 width, automatically allocate the schedule to a dedicated Documentation Sheet (`A-601`). |
| **R-DRW-05** | **Far Clip Truncation on Stepped Facades** | `HIGH` | `MEDIUM` | Setting `FarClipOffset` too tight on an elevation can inadvertently slice off projecting architectural features (e.g., canopies, entrance porches, balconies, or roof eaves). | Calculate `FarClipOffset` as the maximum distance from the elevation cut plane to the farthest building bounding box vertex PLUS a mandatory $2000\text{ mm}$ safety margin. | If projection clipping warning is flagged during inspection, expand far clip offset by an additional $1500\text{ mm}$. |
| **R-DRW-06** | **`FilledRegion` CurveLoop Non-Closure** | `HIGH` | `MEDIUM` | Creating complex hatching in wall-foundation junctions requires perfectly closed, non-self-intersecting `CurveLoop` instances. A $0.1\text{ mm}$ gap or vertex mismatch causes Revit transaction failure. | Build boundary loops using snapped `Line.CreateBound` with endpoints verified via `XYZ.IsAlmostEqualTo(tol = 0.001\text{ ft})`. Run `CurveLoop.IsOpen()` validation prior to calling `FilledRegion.Create`. | If loop closure fails, construct simplified bounding rectangle for the hatch infill and log geometric warning. |
| **R-DRW-07** | **Detail Component Library Path / Language Mismatch** | `MEDIUM` | `LOW` | If Revit is installed in a non-English locale (e.g., German, French) or custom server path, hardcoded paths to `C:\ProgramData\Autodesk\RVT 2026\Libraries\English\US\` fail. | Implement dynamic library discovery: query Revit application data paths via `app.GetLibraryPaths()`. Fallback to relative project paths if default library is missing. | If required RFA cannot be found, fallback to parametric `FilledRegion` with graphic keynote text. |
| **R-DRW-08** | **Native PDF Export Driver & Latency** | `MEDIUM` | `LOW` | Native PDF export (`PDFExportOptions`) requires Revit 2022+ internal PDF driver. Large drawing sets can encounter write locks or timeout if the target PDF file is open in Adobe Acrobat or browser. | Verify file accessibility before export; generate timestamped temporary PDF filenames (`A-101_temp_guid.pdf`) and rename upon successful write completion. | If PDF export fails, fallback to high-resolution PNG export ($300\text{ DPI}$) via `doc.ExportImage`. |
| **R-DRW-09** | **Swallowed Transaction Warnings Hiding Faults** | `HIGH` | `HIGH` | Using `ClashWarningSwallower` without telemetry suppresses critical Revit warnings (e.g., overlapping viewports, unhosted annotations, line off-axis). | Replace `ClashWarningSwallower` with an explicit `DocumentAuditFailurePreprocessor` that logs every suppressed warning into the transaction audit record. | Flag any transaction with $> 5$ suppressed warnings as `WARNING_AUDIT_REQUIRED`. |
| **R-DRW-10** | **Accidental Mutation of User Views/Sheets** | `CRITICAL` | `LOW` | Automated script operating in an existing user project might accidentally rename, re-scale, or hide elements in the client's existing working views. | Enforce strict AI-ownership check: operations are permitted ONLY on views and sheets bearing the `AIGRAV_` prefix or `AIGRAV_Managed == 1` shared parameter. | Abort immediately if the active view is not AI-managed; never mutate user views. |
| **R-DRW-11** | **Annotation Crop Severing External Dimensions** | `MEDIUM` | `MEDIUM` | Activating `AnnotationCropActive` with default boundary clips dimension strings placed outside exterior walls, making dimension text disappear. | Enforce minimum annotation crop offset: the annotation crop box MUST be offset at least $25.0\text{ mm}$ (paper space) outward from the model crop box to accommodate 3 tiers of dimension strings. | Verify dimension element visibility after crop activation; expand annotation crop if severed. |
| **R-DRW-12** | **Scale Recalculation Infinite Thrashing** | `MEDIUM` | `LOW` | If a view fails to fit on a sheet, the engine steps down scale ($1:50 \rightarrow 1:100$). If an unstable relayout triggers another scale adjustment repeatedly, execution could enter an infinite loop. | Enforce a strict maximum iteration limit ($K_{\text{max}} = 2$ scale adjustments). If layout still does not converge, force automated multi-sheet partition (TC-DRW-21). | Hard execution stop after 2 iterations with fallback report to user. |
